# 场景模板库

每个模板只写「必须替换的空」与「容易漏的约束」。默认省略通用部分（自检清单见 SKILL.md）。

---

## 1. 对外文案（种草 / 广告 / 推文）

必填：平台 + 受众 + 3 个卖点 + 预期动作 + 禁用词。

```text
# 角色
你是【平台】内容营销经理，偏好口语、有画面感的短句，不堆形容词。

# 背景
产品：【名称/价格/一句话定位】
卖点：【1】【2】【3】
受众：【年龄段 + 身份 + 他们此刻的处境】
场景：【在哪儿刷到、停留几秒】
成功标准：【看完做什么：点进详情 / 收藏 / 评论】

# 任务
写【3】版【开头 2 行 / 完整正文 / 标题】，供 A/B 测试。

# 要求
- 每版 ≤【40】字；版本之间切入角度必须不同（场景 / 痛点 / 反常识）
- 不用「极致、颠覆、天花板、YYDS」，不用 emoji
- 不承诺参数之外的功能
- 禁止用「你是否也曾…」开头
```

坑：只给卖点不给受众 → 输出变成参数罗列。

## 2. 长文 / 报告

必填：读者层级 + 结论前置要求 + 篇幅 + 引用规则。

```text
# 任务
写【篇幅】的【类型：分析报告 / 综述 / 复盘】，回答【核心问题】。

# 要求
- 结构：结论先行（≤100 字）→ 3–5 个论点（每点含证据）→ 反方视角 → 行动建议
- 每个数据必须注明来源与时间；无来源则标 [待核实]，不得编造
- 不写「随着…的发展」「综上所述」这类套话
- 术语首次出现给一句白话解释
```

坑：不给篇幅 → 输出注水；不给引用规则 → 数据凭空生成。

---

## 3. 方案 / 提案

必填：决策者关心什么 + 约束（预算/人力/时间）+ 备选数量。

```text
# 背景
决策者：【角色，他真正在意的是成本 / 速度 / 风险 / 面子】
约束：【预算】【可用人力】【截止时间】【不可动的东西】
已有：【做过什么、结论是什么、为什么没成】

# 任务
给出【3】个可行方案并推荐一个。

# 要求
- 每个方案：一句话主张 / 关键动作（≤5 步）/ 成本 / 风险 / 失败条件
- 明确写出「什么情况下我推荐的方案会失效」
- 不写无法落地的原则性口号，每条动作要能指派到人
```

坑：只要一个方案 → 无法比较；不写失败条件 → 方案不可信。

## 4. 代码任务

必填：语言/版本 + 运行环境 + 输入输出契约 + 禁止改动范围。

```text
# 任务
在【文件/模块】实现【功能】，满足下列契约。

# 契约
输入：【类型与示例】
输出：【类型与示例】
错误处理：【抛异常 / 返回 null / 重试几次】
性能：【数据量级、时限】

# 要求
- 语言/版本：【】，依赖仅限【】
- 只改【范围】，不动【禁止改动区】
- 先给最小可运行版本，再说明可优化点；不要一次堆抽象
- 不确定的接口/字段标注假设，不要臆造 API
```

坑：不说版本 → 用了不存在的 API；不说禁止区 → 顺手重构整个文件。

## 5. 数据分析

必填：数据字典 + 指标定义 + 分析目的 + 输出形式。

```text
# 背景
数据：【表名/字段含义/时间范围/已知脏数据】
业务问题：【想验证或推翻什么假设】

# 任务
分析【指标】的变化原因，给出结论与下一步。

# 要求
- 先做数据质量检查（缺失率、异常值、口径一致性），再分析
- 指标定义写清口径，口径不同必须分开算
- 结论区分「数据支持的」与「推测的」，后者标 [推测]
- 输出：结论 3 条 → 证据表 → 可验证的下一步
```

坑：不给口径 → 各算各的；不让区分推测 → 结论被当成事实。

## 6. 评审 / 挑错

必填：评审标准 + 严厉程度 + 是否允许改写。

```text
# 角色
你是【领域】的严格评审，只关注会导致失败的问题，不做礼貌性表扬。

# 任务
按下列维度评审【对象】：【正确性 / 完整性 / 可执行性 / 风险】。

# 要求
- 每个问题：位置 + 问题 + 为什么是问题 + 具体改法
- 按严重度排序（阻断 / 重要 / 建议），阻断项不超过 3 条
- 不许泛泛评价「不够深入」；必须指出缺了哪一块
- 最后给一句总体判断：可用 / 修后可用 / 重做
```

坑：不说严厉程度 → 输出全是「整体不错，建议再完善」。

## 7. 翻译 / 本地化

必填：读者语言习惯 + 术语表 + 是否保留原结构 + 禁用直译。

```text
# 任务
把【文本】翻译为【目标语言】，面向【读者身份】。

# 要求
- 术语按表：A→A'、B→B'
- 保留原 Markdown 结构与代码块，不改数字、单位、专有名词
- 按目标语言习惯重组句子，禁止逐词直译；歧义处给「译文 + 原意备注」
- 不增删信息，不擅自本地化案例
```

坑：不说结构保留 → 表格被压平；不说术语表 → 同一术语三种译法。

## 8. 学习 / 讲解

必填：当前水平 + 目标（能做什么）+ 已有误解。

```text
# 角色
你是能把复杂概念讲到外行懂的【领域】讲师，不用比喻堆砌代替机制。

# 背景
我的水平：【完全新手 / 有基础但卡在 X】
目标：【学完能自己做什么具体的事】
已知误解：【我以为是…】

# 任务
讲清【概念】，并纠正我的误解。

# 要求
- 顺序：解决什么问题 → 核心机制 → 一个最小例子 → 常见误解 → 自测题 3 道
- 每段 ≤150 字，术语首次出现给白话解释
- 不做百科式铺陈，不写「总之」
```

坑：不给水平 → 要么太浅要么听不懂；不给目标 → 讲成教材目录。

---

## 9. 决策建议

必填：选项 + 评价维度与权重 + 不可接受的下限。

```text
# 背景
选项：【A / B / C，各一句话】
维度与权重：【成本 30%、速度 40%、风险 30%】
硬下限：【任一选项只要触碰就排除的条件】

# 任务
打分对比并给出推荐。

# 要求
- 表格：选项 × 维度（1–5 分）+ 打分理由（每条 ≤20 字）
- 先筛硬下限，再算加权分
- 明确写出结论对权重变化的敏感度（哪个维度一变结论就反转）
- 信息不足的格子标 [待确认]，不许猜
```

坑：不给权重 → AI 替你定了价值排序。

---

## 10. 信息抽取 / 结构化

必填：目标字段 + 缺失处理 + 输出格式。

```text
# 任务
从【文本】抽取字段，输出 JSON 数组。

# 字段
【name：字符串】【price：数字，单位元】【deadline：ISO 日期，无则 null】

# 要求
- 只输出 JSON，不加解释文字
- 原文没有的字段填 null，不要推断填补
- 一条记录对应一个对象；同一实体多次出现取信息最全的一条
- 单位、币种统一换算后标注原值
```

坑：不说缺失处理 → 模型开始编造；不限定输出 → 前后夹一段解释，解析失败。
